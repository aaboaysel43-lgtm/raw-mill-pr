# Raw Mill PR — دليل التجهيز والنشر

## ما تتضمنه الحزمة
- واجهة عربية RTL متوافقة مع الموبايل واللاب.
- بحث في قطع الغيار، إضافة وتعديل القطع، حركات المخزون، طلبات PR، CSV والطباعة/PDF.
- إعدادات Supabase في `config.js`.
- سياسات RLS في `database_security.sql`.
- بيانات الاستيراد الأصلية موجودة في الحزمة السابقة `Raw_Mill_PR_Import.zip`.

## 1) إكمال إعداد الاتصال
1. افتح Supabase ثم مشروع `raw-mill-pr`.
2. من Project Settings افتح API Keys.
3. انسخ Project URL و`anon`/`publishable` public key فقط.
4. ضع المفتاح العام في `config.js` بدل `PASTE_YOUR_SUPABASE_ANON_PUBLIC_KEY_HERE`.
5. لا تستخدم `service_role` أو secret key داخل المتصفح.

## 2) تفعيل الصلاحيات
بعد التأكد من وجود الجداول واستيراد 2,277 سجلًا:
1. افتح SQL Editor.
2. افتح `database_security.sql` وانسخ محتواه.
3. نفّذه مرة واحدة.
4. من Authentication > Users أنشئ مستخدمًا أو أكثر للمستخدمين المصرّح لهم.
5. لا تفعّل التسجيل العام.

ملاحظة: هذه السياسة تمنح جميع المستخدمين المسجلين صلاحيات تشغيلية واسعة داخل النظام. مناسبة لاختبار فريق موثوق فقط. قبل الاستخدام الرسمي، يفضّل فصل صلاحيات المدير والمستخدم، وتقييد اعتماد PR وتعديل الحالات.

## 3) تشغيل محلي
افتح مجلد المشروع وشغّل خادم ملفات ثابتًا (مثل VS Code Live Server أو `python -m http.server 8000`) ثم افتح `http://localhost:8000`.
لا تفتح `index.html` بالنقر المزدوج لأن بعض المتصفحات تمنع بعض وظائف الملفات المحلية.

## 4) النشر المجاني عبر GitHub Pages
1. أنشئ مستودع GitHub جديدًا باسم `raw-mill-pr`.
2. ارفع الملفات: `index.html`, `styles.css`, `app.js`, `config.js`.
3. من Settings > Pages اختر Deploy from a branch، ثم `main` و`/ (root)`.
4. انتظر رابط Pages الذي يعرضه GitHub.
5. في Supabase Authentication > URL Configuration أضف رابط Pages إلى Site URL وRedirect URLs.
6. اختبر الدخول والقراءة والإضافة من جهازين.

GitHub Pages يستضيف واجهة ثابتة فقط؛ Supabase يبقى قاعدة البيانات السحابية. الخطة المجانية لها حدود وشروط قابلة للتغيير.

## تنبيهات مهمة
- تم استيراد بيانات القطع من الملف الأصلي. الرصيد والحد الأدنى يبدأان من صفر لأن الملف الأصلي لا يثبت أرصدة فعلية.
- التطبيق لا ينشئ حسابات ولا يفعّل التسجيل العام.
- تأكد من تنفيذ `database_security.sql` قبل اختبار الواجهة؛ لأن الجداول الحالية لديها RLS مفعّل.
- لا تشارك أي مفتاح `service_role` أو كلمة مرور قاعدة البيانات.
- حركة التسوية تطلب الرصيد الفعلي الجديد. اختبرها أولًا بقطعة تجريبية قبل التشغيل الفعلي.
- لا تعتبر النظام جاهزًا للتشغيل الرسمي قبل اختبار تسجيل الدخول، الصلاحيات، حركات المخزون، وطلبات PR.
